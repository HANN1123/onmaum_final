# 측정 화면 카메라 구도 복원

2026-11-05 · `feat/rppg-tuned-camera-restore` · 비교 기준 `6fd22ac`

## 변경 범위와 판단

- `useWebcam.ts`: `frameRate: { ideal: 30 }`을 제거해 예전의 전면 카메라·1280×720 선호 요청으로 복원했다. 센서 모드 선택에 따른 화각 차이를 피하기 위한 변경이다. 같은 훅을 쓰는 `HeroDark`, `HeroDemo`, `OrbLab`에도 적용된다.
- `measureDemo.module.css`: #33의 26vh/22vh 높이 제한과 창 비율 기준 열 전환을 제거했다. 예전의 1.55:1 열 비율, 폭 1100px 전환점, 간격·파형 높이·측정 화면 상단의 내재 크기를 복원했다. 계기판의 최소 너비도 카메라 크기에 영향을 주므로 해당 측정 화면의 축소 규칙을 함께 되돌렸다. 설문 등 다른 화면의 규칙은 유지했다.
- `MeasureDemo.tsx`: 절대 위치로 회전하는 영상 옆에 빈 SVG 대체 요소를 두어 예전 video와 같은 내재 크기를 확보했다. 크기는 `videoWidth`·`videoHeight`를 기존 `rotatedSize`로 돌린 값이다. 고정 16:9를 사용하지 않으므로 4:3·90°·270°도 대응한다. 표시 계산에는 소수 픽셀을 보존한다.
- 본문은 휠·터치·키보드로 스크롤한다. 스크롤바가 차지하는 폭 때문에 Windows에서 구도가 15px 바뀌지 않도록 막대만 숨겼고, 본문에 키보드 초점을 줄 수 있게 했다. 상단 측정 종료는 유지한다.
- 담당 범위는 ① 카메라·rPPG/④ UI(김우빈)와 요청된 분석 문서다. 공유 파일(`package*.json`, 전역 CSS, 설정, `.gitignore`), 저장 구조·공개 타입·rPPG 결과 계약의 변경은 없다. Electron 창·위젯, 워치, 설문을 변경하지 않았다.
- 얼굴·감정·rPPG 처리 경로는 변경하지 않았다. 실제 video 원본 해상도를 사용하며, 기존 회전 시 원본 프레임을 회전하는 처리도 그대로다. SVG는 화면 배치 전용이다.

## 측정 화면 rPPG 확인

사용자가 지정한 RAVDESS Actor_01 영상은 파일을 복사하지 않고 메모리에서 읽어 video를 반복 재생하고 `captureStream()`으로 공급했다. 짧은 반복 영상은 심박 정확도 검증에 사용하지 않았다. `useHeartRateSource` → `useMeRppg` → 튜닝된 `hrEstimator` 경로를 코드와 실제 워커 출력으로 확인했다.

Windows 하드웨어 GPU(ANGLE/D3D11, RTX 5060 Ti)에서 확인한 결과:

| 입력 | 확인한 상태 | 결과 |
|---|---|---|
| 원본 얼굴 영상 반복 | 약 17초 ‘신호 모으는 중’ → 36초 ‘신호 약함’ → 52초 숫자 72 및 ‘측정 중’ | 얼굴 상자·‘얼굴 추적 중’·‘평온’ 표시 유지, 워커 출력 1,725개, 워커 오류/JS 예외 0 |
| 같은 영상에 좌우 ±60px·1.1Hz 이동을 합성한 1280×720 캔버스 | 약 9초 ‘신호 모으는 중’ → 30초 ‘움직임 감지’ | SNR이 양수인 구간에도 숫자 대신 `--` 유지, 워커 출력 1,025개, 워커 오류/JS 예외 0 |

두 경우 모두 측정 종료 후 `/demo/result`로 이동했다. 움직임 시험은 상태 게이트 확인용 합성 입력이며 실제 사용자 움직임 정확도 평가가 아니다. 처음 시도한 SwiftShader 소프트웨어 GPU에서는 낮은 FPS로 신호가 반복 초기화되어 ‘신호 모으는 중’에 머물렀다. 이를 실제 카메라나 엔진 고장으로 해석하지 않고, 하드웨어 GPU로 다시 확인했다.

콘솔 예외·rPPG 워커 오류와 구분할 로그가 있다. MediaPipe가 `console.error` 경로로 `INFO: Created TensorFlow Lite XNNPACK delegate for CPU.`를 출력했고, 환경의 네트워크 제한으로 `https://odml.pa.googleapis.com/v1/log` 요청에 `net::ERR_NETWORK_ACCESS_DENIED`가 발생했다. 따라서 “콘솔 오류 0건”이라고 보고하지 않는다. 이번 표시 복원과 무관한 기존 라이브러리 동작으로, 이 작업에서 수정하지 않았다.

시각 검증은 3041이 제공하는 **동일 폰트 파일**을 `.eval/camera-compare/`에 받아 임시 `NEXT_FONT_GOOGLE_MOCKED_RESPONSES`에 data URL로 넣어 빌드했다. 최종 빌드·정적 페이지 생성은 성공했다. 앱의 폰트 소스나 의존성을 변경하지 않았고, 브라우저 폰트 로딩 실패가 없는지도 확인했다. 이 환경의 폰트 다운로드 실패가 Mac에서도 발생하는지는 별도 확인해야 한다.

Chrome 임시 프로필만 이미 무시되는 `node_modules/.cache/` 아래에 있다.

남은 실기 확인은 MacBook 실제 카메라의 센서 모드·실제 FPS·Electron 창 안에서의 표시다. 프레임률 선호를 제거했으므로 실제 FPS는 카메라가 선택하며, 낮은 프레임률은 기존 rPPG 품질 게이트가 처리한다. 이 검증은 브라우저의 표시·상태 전환 검증이며 실제 심박 정확도나 Mac Electron 패키지 실행을 보증하지 않는다. 커밋·push·브랜치 전환은 수행하지 않았다.
