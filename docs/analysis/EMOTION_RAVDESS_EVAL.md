# RAVDESS 감정 영상 평가

## 결론

배우 01, 03, 04의 실영상을 평가했다. 배우 단위 교차검증 결과는 아래와 같다. 가운데 60% 프레임 정확도는 기존 71.79%, 배우 보류 교차검증 후보 72.29%로 0.50%p 차이다. 영상 다수결 정확도는 73.48%→71.97%다. 원본 neutral 재현율은 100.00%→100.00%, calm은 41.28%→44.95%다. 런타임 알고리즘은 변경하지 않았다. 독립 배우에서 neutral·calm 성능을 보존하는 일반화 개선 근거 없이 가중치를 배포하지 않는다.

## 작업 범위

교차검증 후보는 3개 fold 모두 3표본 다수결 창이었다. 가운데 구간의 정답 프레임은 860/1,198에서 866/1,198로 6개 늘었지만, 정답 영상은 97/132에서 95/132로 2개 줄었다. 사전 기준인 프레임 정확도 +2%p에도 못 미쳐 채택하지 않았다. 따라서 실제 배포 코드의 튜닝 전·후 성능은 동일하다.

평가 스크립트와 지표 테스트를 추가했다. 공용 파일 변경은 로컬 산출물을 제외하는 .gitignore의 /.eval/과 eslint.config.mjs의 .eval/**뿐이다. features/camera/**, features/ui/**, features/rppg/**, 모델 자산, 공개 함수 시그니처와 EmotionResult는 그대로다.

## 데이터와 출처

- 평가 영상: 180개, 배우 01, 03, 04. 나머지 배우는 이번 결과에 포함하지 않았다.
- 실행 목록을 확정한 시각은 2026-11-04 20:33 KST다. 배우 02 ZIP은 183,415,392바이트에서 내려받기가 중단됐고 ZIP 중앙 디렉터리를 읽을 수 없어 제외했다. 데이터셋 파일을 삭제·이동하거나 직접 압축 해제하지 않았다.
- 배우마다 60개 영상이며 남성 2명(01·03), 여성 1명(04)이다. 가운데 구간 1,613프레임 중 4종 정답이 있는 프레임은 1,198개, 전체 2,770프레임 중에는 2,067개다. 정확도 대상 영상은 132개, fearful·surprised 영상은 48개다.
- 음성 발화 영상(VV=01)만 선택하고 MM=02를 우선한다. MM=01은 같은 나머지 파일명이 있는 MM=02와 중복 집계하지 않는다.
- 정답: neutral·calm→calm, happy→happy, sad→sad, angry·disgust→angry. fearful·surprised는 정확도 분모에 넣지 않는다.
- 원본: [RAVDESS, Zenodo](https://zenodo.org/records/1188976), 데이터 라이선스 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/), 비상업 연구용.
- 인용: Livingstone, S. R., & Russo, F. A. (2018). The Ryerson Audio-Visual Database of Emotional Speech and Song (RAVDESS). PLOS ONE 13(5), e0196391. [doi:10.1371/journal.pone.0196391](https://doi.org/10.1371/journal.pone.0196391).
- 원본 영상·얼굴 이미지·추출 프레임은 커밋하지 않았다. 확률 JSONL과 Chrome 프로필은 .eval/에만 남긴다.

## 방법

설치된 Vite 8로 Next.js 빌드 없이 테스트 전용 브라우저 번들을 만들었다. 설치된 Chrome을 headless CDP로 실행하고 localhost의 영상만 읽는다. 앱의 getBlazeFace, expressionsFromBox, loadFaceApiModels, normalizeExpressions, smoothEmotion, getDominantEmotion, nextPresence를 직접 import한다. BlazeFace는 앱과 같은 CPU delegate, VIDEO 모드, short-range 모델, 검출 임계값 0.5이며 얼굴 상자를 각 방향 10% 넓힌다. 68점 랜드마크와 alignedRect를 거쳐 faceExpressionNet을 실행한다.

각 영상 t=0부터 250ms 간격의 원본 시각으로 순서대로 탐색한다. 프레임 처리 속도와 관계없이 4fps 표본을 빠뜨리지 않는다. EMA α=0.4와 감정 상태를 영상마다 초기화하고 3회 연속 미검출 시 초기화한다. 가운데 60%는 0.2×duration ≤ t < 0.8×duration이다. 가운데 구간 전에 들어온 EMA 이력도 유지한다. rPPG 파형 추론과 실제 카메라 타이머의 busy·stale 프레임 건너뛰기는 재현하지 않는다.

JSONL에는 영상 ID·배우·감정·강도·시각·길이·얼굴 검출 여부, raw 7종, 정규화 4종, EMA 4종, 우세 감정을 저장한다. 미판정은 기본 프레임 정확도에서 오답이며, 잠깐의 미검출에 유지된 UI 판정은 그대로 평가한다. 조건부 정확도는 미판정만 제외한다. 얼굴 검출률과 표정 산출률은 별개이며, 4종 정답 밖 영상도 얼굴 검출률 분모에 포함한다. 다수결 영상 정확도는 판정된 표본의 최빈값을 쓰고 전부 미판정인 영상은 오답이다. 동률은 앱과 같은 happy, calm, sad, angry 순서로 결정한다. 정밀도 분모가 0이거나 해당 정답이 없으면 산출 불가로 표시한다.

최종 평가는 Chrome 기본 GPU 설정의 face-api WebGL 백엔드로 처리했다. 초기 CPU 탐색 결과는 최종 지표에 섞지 않았다. BlazeFace의 delegate는 앱과 같은 CPU다. 하드웨어·백엔드에 따른 부동소수점 차이가 있을 수 있다. 시간순 표본 재생 평가이며 실시간 처리량이나 지연 평가가 아니다.

## 튜닝과 배우 단위 교차검증

사전 고정한 32개 후보: 기존 설정, α 0.2·0.6·0.8·1, 후행 다수결 창 3·5·9표본, 각 클래스 단일 가중치 0.5·0.75·1.5·2, fearful 또는 surprised 확률을 각 4종 중 하나에 합산하는 후보를 비교한다. EMA와 투표는 영상마다 초기화한다. 후보 선택 목적은 가운데 60% 프레임 정확도이며, 학습 쪽 neutral·calm 재현율이 기존보다 낮아지는 후보는 제외한다. 동점은 기존 설정을 우선한다. 배우 1명을 통째로 보류하고 나머지 배우만으로 후보를 선택해 그 보류 배우에만 점수를 낸다. 같은 배우의 다른 영상을 학습·평가로 나누지 않는다. 모든 보류 결과를 합친 점수는 배우마다 다른 선택 후보를 사용한 선택 절차의 성능이며, 단일 배포 후보의 성능을 뜻하지 않는다.

변경 근거의 최소 기준은 보류 결과 프레임 정확도 +2%p, 모든 보류 배우에서 정확도·neutral·calm 재현율 비감소다. 적은 배우로 통계적 유의성을 주장하지 않는다. 이 기준을 통과해도 고정한 배포 후보의 추가 독립 검증이 필요하다.

## 한계와 후속 작업

RAVDESS는 연기된 표정과 말하는 얼굴이므로 평상시 쉬는 얼굴, 자연스러운 미세 표정, 실제 마음 상태의 정답이 아니다. 평가된 배우 수가 적고 서양인 위주의 데이터라 한국인 사용자·다양한 연령·조명·카메라·피부색으로 일반화할 수 없다. neutral·calm 재현율을 따로 제시했지만 실제 휴식 얼굴의 성능 비감소를 입증하지는 못한다. 영상 감정 라벨을 모든 표본에 적용하므로 가운데 60%에서도 발화·표정 시작과 끝의 라벨 잡음이 남는다.

추가 배우 다운로드가 완료되면 같은 명령으로 재실행하고, 정면 휴식·발화·자연 표정 동의 데이터로 독립 확인한다. 카메라·UI·rPPG 경로 변경은 이번 근거로 제안하지 않는다.

## 재현과 검사

루트에서 실행한다. Node 22.20.0, 현재 lock 파일의 Vite·MediaPipe·face-api와 설치된 Chrome을 사용한다. 새 의존성은 추가하지 않았다.

```powershell
node scripts/analysis/emotion-ravdess/run.mjs '<RAVDESS 루트>'
node scripts/analysis/emotion-ravdess/report.mjs '.eval/summary-<시각>.json'
node scripts/analysis/emotion-ravdess/run.mjs --smoke
npm.cmd run check
npx.cmd tsc --noEmit
git diff --check
```

실행 시점 목록은 .eval/inventory.json, 소스·모델 SHA-256은 .eval/provenance.json, 영상별 확률 캐시는 .eval/records-native/, 합친 프레임은 .eval/frames-*.jsonl, 상세 지표와 fold별 후보 선택 근거는 .eval/summary-*.json에 남긴다. 캐시는 소스·모델 해시와 원본 크기가 같을 때 재사용한다. 하네스 자체를 수정했거나 원본을 교체했으면 --fresh를 붙여 캐시를 무시한다. 데이터셋은 읽기만 하며 ZIP 해제·삭제·이동은 하지 않는다. --smoke는 단색 합성 영상으로 영상 탐색·모델 로드·미검출 경로만 검증하므로 실영상 정확도 근거로 사용하지 않는다.

최종 Chrome 버전은 156.0.8078.80이며 최종 180개 영상의 face-api 백엔드는 모두 WebGL이었다. 입력 해상도는 1,280×720이다. 상세 실행 결과는 `.eval/summary-2026-11-04T11-33-32-387Z.json`, 프레임은 같은 시각의 JSONL에 있다.

| 검사 | 결과 |
|---|---|
| `npm run check` | 도구 테스트 7개 통과, 앱 테스트 549개 통과·기존 recorder skip 4개 유지. lint와 Electron 타입 검사 통과. 빌드는 기존 Google Fonts의 JetBrains Mono·Sora 다운로드가 네트워크 접근 제한으로 실패해 전체 통과하지 못함 |
| `npx tsc --noEmit` | 통과 |
| `git diff --check` | 통과 |
| 합성 영상 검사 | 4프레임, 미검출 처리 통과. CPU 진단 실행이며 최종 실영상 지표와 분리 |
| 새 지표 검증 테스트 | 7개 통과. 구간·정답 제외·미판정·EMA 초기화·후보 재생·배우 부족·보류 배우 누수 방지 검증 |

lint의 기존 경고 2건(`CameraView.tsx`의 ref 정리, `DataManagement.test.tsx`의 미사용 변수)은 이번 범위에서 수정하지 않았다. Google Fonts 직접 요청도 `EACCES`로 거부됐다. 외부 폰트를 대체하거나 응답을 모의 처리해 빌드 성공으로 기록하지 않았다. 네트워크 접근이 가능한 환경에서 `npm run check` 전체 통과를 다시 확인해야 한다.

전체 검사에서 빌드까지 진행한 로그는 `.eval/check.log`에 있다. 앱 테스트를 다시 실행한 `.eval/check-final.log`에서도 549개 통과·skip 4개를 확인했으나, 재실행은 lint 단계에서 중단했으므로 전체 통과 근거로 사용하지 않았다.

## 인계 상태

파일 변경은 `feat/emotion-ravdess-eval` 작업 폴더 안에만 남겼고 push하지 않았다. 커밋을 위해 `git add`를 실행했으나, 작업 폴더 밖의 공유 Git 메타데이터 `index.lock` 생성이 `Permission denied`로 거부됐다. 이 실행 환경에서는 커밋을 만들지 못했으며 새 커밋 해시는 없다. 파일시스템 쓰기 권한이 있는 환경에서 변경 내용을 검토하고 커밋해야 한다. 준비한 커밋 메시지는 `.eval/commit-message.txt`이며 요청한 Co-Authored-By 줄을 포함한다.
