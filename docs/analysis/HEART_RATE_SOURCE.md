## 범위와 소유권

현재 `feat/rppg-tuning-shared-face` 워크트리에서 측정 UI·rPPG 출처 선택·세션 결과를 연결한다. 김우빈 담당 rPPG·UI와 개인 상태 분석에서 소비할 기록 계약의 교차 영역 변경이다. 실제 저장 계층 `shared/storage/**`, 카메라·Electron, 실험실·워치 비교 패널, rPPG 추정·게이트·실시간 다듬기 파라미터는 바꾸지 않는다. 커밋·push는 하지 않는다.

## 선택 규칙

- 연결된 워치의 마지막 표본이 유한한 시각·30~220 BPM이고, 같은 `performance.now()` 기준으로 `0 ≤ now - t ≤ 8000`이며 접촉 불량이 아니면 워치를 표시한다. 접촉 지원 없음은 허용한다.
- 워치 행과 선택기가 `heartRateSource.ts`의 상수·유효성 함수를 공유한다. 8초는 실측 알림 간격이 5초를 9회 넘었고 최대 6.06초였다는 근거로 정했다.
- 연결 해제·접촉 불량·범위 밖 값은 즉시 카메라로 전환한다. 무수신은 8초 초과 시 전환한다. 경계 다음 1ms 타이머를 따로 두어 1초 갱신 주기 때문에 만료가 늦어지지 않게 한다. 백그라운드 타이머 지연은 브라우저 제약으로 남는다.
- 정상 새 알림 한 번이면 워치로 복귀한다. 추가 확인 횟수·히스테리시스·숫자 보간은 없다. 수신 횟수를 누적하지 않는 순수 선택이므로 같은 표본 재평가가 추가 수신으로 계산되지 않는다. 화면은 매번 초기 상태로 평가하며 최초 연결·재연결·측정 재시작 사이에 선택 이력을 공유하지 않는다.
- 두 원천 모두 없으면 값과 출처가 없다. 카메라 품질이 good이 아니면 `카메라 · 참고값`으로 표시한다.
- 워치 숫자·오브의 준비 조건은 카메라·모델 준비와 분리한다. 신호 상태 행·파형 칸은 계속 rPPG이다.
- rPPG 원추정이 있으면 실제 파형으로 오브를 움직인다. 없고 워치가 선택됐으면 수신 BPM 기반 주기 애니메이션을 사용한다. 실측 파형이 아니며, 경과 시간 적분으로 BPM 변경 때 위상이 튀지 않게 한다. 측정 종료 시 표시·박동·표본 수집을 멈춘다.

## 공개 계약 변경

| 계약 | 변경 내용 |
|---|---|
| `TimelinePoint` | 선택 필드 `source`, `watchBpm`, `watchAgeMs`, `watchContact`, `rppgBpm` 추가. 기존 `bpm`은 실제 선택값이다. |
| `quality`, `rawBpm` | 선택 출처와 관계없이 rPPG 메타데이터로 유지한다. 워치 때문에 good으로 바꾸지 않는다. |
| `watchBpm` | 해당 초에 관측한 마지막 워치 원수신값이다. 만료·접촉 불량 값도 기록한다. 연결 훅이 마지막 표본을 지우면 null이다. |
| `watchAgeMs` | 표본을 기록하는 순간의 `performance.now() - latest.t`다. 시각이 없거나 계산이 비유한수면 null이다. |
| `useSessionLog` | 기존 인자·반환은 유지하고 여섯 번째 선택 인자 `SessionLogSources { latest, status, rppgBpm }`를 추가한다. 표본 채집·종료 시 선택기를 다시 실행한다. |
| `useWatch` | 기존 인자·행 문구·버튼을 유지하고 반환에 `latest`, `status`, `now`를 추가한다. |
| `WATCH_STALE_MS` | 5000 → 8000. 정의를 rPPG 라이브러리로 옮기고 기존 `watchStatus.ts` 경로에서도 재노출한다. |
| `BpmSample` | 선택 필드 `source` 추가. 출처가 명시된 기록의 워치는 정리하지 않는다. |
| `SessionSummary` | 정리 후 유효 심박 표본 수 기준 `sourceShares` 추가. 모두 없으면 양쪽 0이다. |
| `smoothBpm` | 두 번째 선택 인자에 표본 배열을 받아 출처 구간을 구분한다. 기존 숫자 배열 호출은 유지한다. |

출처 없는 옛 기록은 유효 BPM이 있는 표본만 카메라로 해석한다. 새 기록에서 값이 없으면 `source`를 생략한다. 저장 키·세션 버전·DB schema 변경은 없다.

## 정리와 결과

워치 선택값은 Hampel 정리와 그래프 이동평균 모두에서 보존한다. 카메라 정리·다듬기는 같은 출처의 연속 구간 안에서 수행하고 워치를 기준값으로 쓰지 않는다. null, MAX_JOIN_GAP_SEC(3초)를 넘는 시간 공백, 시간 역행에서 구간을 끊는다(창 최소화 등으로 1초 타이머가 밀려 t 가 2~3초 건너뛰는 경우는 잇는다). 출처 없는 옛 입력과 포스터·소개 화면의 기존 정리·이동평균 호출은 이전 동작을 유지한다.

평균·최고·가장 높았던 구간은 사후 정리한 선택값에서 구한다. 그래프용 이동평균과 구분한다. 출처 비율 분모는 정리 후 유효 BPM 표본 수이며, 없으면 `심박 기록 없음`을 표시한다.

그래프 기본선·강조선 모두 워치 불투명도 1, 카메라 0.55를 적용한다. 기존 dash 기반 그리기 애니메이션과 충돌을 피하기 위한 선택이다. 인접한 출처 전환점은 다음 출처 스타일의 선으로 연결하고, null·시간 공백은 연결하지 않는다. 단일 표본은 점으로 표시한다. 출처가 둘이면 스타일 설명, 하나면 출처 표지만 표시한다.

## 재생 시험

원본 `.eval/real/rppg-lab-wave-2026-11-04-13-38.json`의 BVP와 상자를 합쳐 시간순으로 처리했다. 매초 앱의 추정기 → 게이트 → 표시 다듬기 → 선택기를 실행했다. 미래 표본은 넣지 않았다. 원본 워치는 별도 보존하고, 오차 평가에서만 `rPPG(t)`를 `watch(t+6초)`와 비교했다. 6초는 단일 실측 추정이며 보편적 보정값이 아니다. markers는 비어 있다.

120초부터 알림을 20·60초 제거하되 BLE 연결은 유지한 무수신, 120–140초 접촉 불량, 120–140초 BLE 해제를 각각 삽입했다. 최초 워치 수신은 약 58.2초다. 전환 횟수는 두 유효 출처 사이 전환만 센다.

| 시나리오 | 워치/카메라/없음 표본 수 | 전환 수 | 전환 점프(BPM) | 전체 대체 MAE(쌍) | 삽입 이후 대체 MAE(쌍) |
|---|---:|---:|---|---|---|
| 원본 알림 | 290/39/19 | 1 | 4.54 | 2.49 (6) | 해당 없음 |
| 20초 무수신 | 273/56/19 | 3 | 4.54, 0.14, 2.80 | 1.73 (23) | 1.46 (17) |
| 60초 무수신 | 233/96/19 | 3 | 4.54, 0.14, 2.19 | 2.19 (63) | 2.16 (57) |
| 20초 접촉 불량 | 266/63/19 | 3 | 4.54, 6.14, 2.80 | 3.42 (30) | 3.66 (24) |
| 20초 BLE 해제 | 266/63/19 | 3 | 4.54, 6.14, 2.80 | 3.42 (30) | 3.66 (24) |

원본 출처 타임라인은 1–6초 없음 → 7–9초 카메라 → 10–22초 없음 → 23–58초 카메라 → 59–348초 워치다. 무수신은 127초에 카메라로 전환하며 각각 144·184초 정상 알림에 복귀한다. 접촉 불량·BLE 해제는 120초 즉시 전환하고 144초 정상 알림에 복귀한다. 시작 전 워치가 없는 대부분 구간은 비교용 기준값도 없어 MAE 쌍 수가 적다.

재현 명령은 `npx.cmd vitest run --config .eval/source-replay.config.mts`다. 스크립트·설정·표본별 JSON·타임라인 보고서는 `.eval/source-replay*`에 있으며 git 무시 대상이다.

## 실측 확인 항목

워치 약 6초 지연 때문에 같은 순간 두 원천의 값이 다를 수 있으며 출처 전환 시 그대로 점프한다. 이 기록의 최대 전환 점프는 6.14 BPM이지만 움직임·운동 때 더 클 수 있다. HeartCast 접촉 상태·무수신·BLE 연결 해제·수동 재연결, 카메라 실패 중 워치 표시, 백그라운드 복귀 시 만료 처리와 작은 화면 출처 표지 배치를 실제 기기로 확인해야 한다. 이번 시험은 기록 재생과 컴포넌트 시험이며 실제 워치 연결 시험을 대신하지 않는다.
