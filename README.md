# 온마음 (ONMAUM)

웹캠 표정 분석과 스스로 남긴 응답으로 **일상에서 자기 마음을 살피고 돌보도록 돕는** 개인용 마음 관리 웹앱입니다.

서버·계정 없이 브라우저에서만 동작하며, 기록은 기기 안(IndexedDB·localStorage)에만 남습니다. 의료 진단이 아니라 자기 인식을 돕는 도구입니다.

## 방향

자세한 방향은 [docs/roadmap.md](docs/roadmap.md)에 있습니다.
1학기 정리: [docs/2026-1학기-정리.md](docs/2026-1학기-정리.md)

1. 카메라 기반 인식 고도화 — DeepMedi류 rPPG/심박 참고, 웹캠 신호 안정화
2. Electron — 브라우저 PWA 대신 PC 앱, 백그라운드(숨김 창)에서도 측정 가능
3. 서버 연동 · 관리자 페이지 — 개인용 앱으로 방향을 정하면서 현재 개발 범위에서 제외(2026-10-18)
4. UI 변경 — 세부 톤은 추후 확정
5. 감정 분석 알고리즘 체계화 — 규칙·임계값·단계(로컬 점수 → 필요할 때만 AI)를 문서/코드로 고정
6. 피드백 — 자기 상태를 돌아보고 잠시 쉬어 갈 수 있도록 안내. 지금은 준비된 문구와 사용자 선호로 고르며, AI 조언은 향후 검토. 분석 결과로 실제 감정이나 스트레스 정도를 단정하지 않고 “컨디션 신호 / 참고용”으로 보여 줌. 의료·진단 뉘앙스 금지.

## 왜 만들었나

바쁘게 지내다 보면 내 기분을 돌아볼 여유를 놓치기 쉽습니다. 온마음은 기록과 간단한 체크인으로 하루를 돌아보고, 잠시 쉬어 갈 계기를 만드는 것을 목표로 합니다.

예를 들어 고객을 응대하며 감정을 드러내기 어려운 **감정노동자**처럼, 일하는 동안 자기 감정을 뒤로 미뤄 두는 사람도 자신의 상태를 돌아보는 데 쓸 수 있습니다.

기록은 서버로 보내지 않고 사용자의 기기에만 보관합니다. 회사나 기관이 사람을 지켜보는 도구가 아닙니다. **의료기기가 아닙니다.**

## 하는 일

컴퓨터 앞에서 일하거나 공부하는 동안 웹캠으로 표정을 분석합니다. 결과를 기쁨·평온·슬픔·화남 네 가지로 나눠 1분 단위로 기록하고, 이를 바탕으로 하루의 긍정 지수와 스트레스 지수를 보여 줍니다. 기록이 충분히 쌓이면 이전 기록으로 만든 개인 기준선과 비교한 “평소 대비” 상태도 표시합니다. 이 지수는 자기 상태를 돌아보기 위한 참고 정보입니다. 푸터에 상담 전화(1577-0199, 109)를 둡니다.

측정은 **측정 시작**을 누른 뒤 **측정 종료**를 누를 때까지만 돌아갑니다. 탭을 내리거나 백그라운드로 두면 브라우저 제약으로 측정이 느려지거나 멈출 수 있습니다.

## 주요 기능 (현재)

- **측정** — 웹캠 표정 분석, 1분 자동 저장
- **오늘 리포트** — 긍정/스트레스 2축, 이전 기록 기반 개인 기준선
- **체크인 보정** — 오전·오후 자기보고로 스트레스 표시를 소폭 조정
- **옵트인 넛지** — 기본 꺼짐. 권한 허용 시 인앱 배너·브라우저 알림
- **Document PiP 오브** — Chrome/Edge 등 지원 시 작은 오브 창 (분석 루프는 원래 탭에 남음)
- **PWA** — 홈 화면 설치, `public/models/`에서 얼굴 인식 모델 서빙
- **상담 전화 안내** — 1577-0199, 109

## 실행 방법

Claude·Codex로 구현하고 필요할 때 Gemini CLI로 검토하는 팀 작업은 [Orca 협업 가이드](docs/collaboration/ORCA_WORKFLOW.md)를 따릅니다.
Node 버전은 `.node-version`을 기준으로 맞춥니다.

```bash
npm run setup:workspace # lock 파일 기준 설치
npm run dev          # http://localhost:3000
npm run test:run     # 단발 테스트
npm run check        # 도구 테스트 → 앱 테스트 → lint → build
npm run build && npm start
```

환경 변수는 없습니다. 카메라는 HTTPS(또는 localhost)와 권한 허용이 필요합니다. 얼굴 인식 가중치는 `public/models/`에서 서빙되며 합계는 약 6.5MB입니다.

테스트 (최근 확인 기준): 파일 30개, **139 passed / 4 skipped**. 레코더 통합 테스트 일부는 아직 `skip`입니다.

배포 예: [https://onmaum.vercel.app](https://onmaum.vercel.app) (Vercel). 별도 서버·API 키 없음.

```
app/            라우트 — /, /measure, /stats, /demo, /orb-preview
features/camera/     ① 카메라·모델·측정 루프 — 김우빈
features/ui/         ④ 화면·오브·Document PiP — 김우빈
features/algorithm/  ⑤ 감정·스트레스·기준선 — 이정환
features/feedback/   ⑥ 체크인·넛지·알림·자기관리 제안 — 이정환 (components는 공동)
shared/storage/      공통 저장 기반 — 이정환 주 관리, 공동 주의
public/         PWA(manifest, sw.js), face-api 모델
tests/          camera, ui, algorithm, feedback, shared 및 tooling
docs/           architecture, collaboration, 기존 설계 스펙·구현 계획
```

전체 파일 구조와 이동 경로는 [프로젝트 구조](docs/architecture/PROJECT_STRUCTURE.md),
담당 영역과 공동 관리 기준은 [코드 소유권](docs/collaboration/CODE_OWNERSHIP.md)을 참고합니다.
① rPPG(김우빈)는 향후 `features/rppg/`, ② Electron(김우빈)은 향후 `features/electron/`에 구현합니다. 현재는 두 디렉터리와 기능을 생성하지 않았습니다. ③ 개인 데이터 관리(이정환)는 현재 `shared/storage/`가 중심이며, 관리자 페이지와 조직·직원 관리는 현재 개발 범위에서 제외합니다.
비어 있는 `features/feedback/components/RiskAlert.tsx`, `features/feedback/lib/notification.ts`는 빈 상태로 이동했습니다.

데이터 흐름: Camera/Detection → 기존 `RawExpressions` → Algorithm 정규화·집계·Stress/State → Feedback 조건·문구 → UI 표시. `useEmotionRecorder`가 약 0.5초 분석·1분 집계를 연결하며 기록은 `shared/storage`의 Dexie `emotions`에 저장합니다. 알고리즘 결과·카메라 옵션·UI·DB schema는 재분류 전과 같습니다.

설계 세부(알고리즘, Electron 창 구조 등)는 `docs/`를 보세요. 이 README는 지금 쓸 수 있는 기능과 앞으로의 계획(아래 로드맵)을 구분해 적습니다.

## 한계와 주의

- **의료기기가 아닙니다.** 진단·치료 목적이 아니며, 자기 인식 보조에 가깝습니다. 도움이 필요하면 정신건강위기상담전화 **1577-0199**, 자살예방상담전화 **109**(24시간)을 이용해 주세요.
- 표정만으로 마음 상태를 추정하므로, 분석 결과는 실제 감정이나 부담의 정도와 다를 수 있습니다. 조명, 얼굴 각도, 말하기, 얼굴이 감지되지 않는 구간에 따라 값이 흔들릴 수 있습니다. 감정을 겉으로 드러내지 않거나 일부러 표정을 지을 때(예: 감정노동자의 업무 중 표정 관리)는, 표정에 드러나지 않은 감정이나 부담이 분석 결과에 반영되지 않을 수 있습니다.
- 기록은 암호화·잠금 없이 브라우저 저장소에만 있습니다. 공용 PC에서는 OS 계정 분리가 사실상 경계입니다.
- 백그라운드·다른 탭에서는 측정이 보장되지 않습니다. PiP는 오브만 띄우고, 분석 루프는 원래 탭에 남습니다.

## 로드맵 (계획 · 미구현)

아직 코드에 없거나 방향만 정한 항목입니다. 기대한 기능처럼 쓰지 마세요.

### 다음에 손댈 순서

1. **측정 단위 기록 (확정)** — “측정 시작~종료”를 한 세션으로 묶어 측정별 요약과 하루 동안의 지표 변화 표시
2. **Electron 숨김 측정 실험 (선행)** — Windows에서 창을 내려도 카메라 측정이 이어지는지 확인. 실패하면 PC 전환 전제를 다시 검토
3. **UI 구성 검토** — 측정 후 간단히 답하는 체크인 화면과 측정별 기록을 시간순으로 보여 주는 구성을 기본안으로, 오브/가장자리 빛/트레이는 선택 모드로 검토

### 그다음 검토

- **Electron PC 프로그램 · 항상 위 오브 (방향)** — 웹 PWA 대신 Windows 우선 데스크톱
- **바우처 안내 (계획)** — 정신건강 심리상담 바우처사업 등 공식 안내·링크
- **카메라 심박(rPPG) (미구현 · 설계안 리뷰 중)** — 카메라 영상으로 심박수를 추정해 표정 분석과 함께 쓰는 핵심 기능으로 준비 중. 통합 설계안(PR #15)에서는 심박변이도(HRV)를 1차 범위에서 제외
- **음성 (계획 · 미구현)** — 본인 목소리의 높낮이와 말하는 리듬을 활용하는 방안 검토
